## Specification
<!-- SPECIFICATION:BEGIN -->
Modernize the model catalogs and request/response handling for five providers — xAI, Mistral, native DeepSeek, Copilot, and OpenRouter — so Converse advertises only current flagship / latest-generation models while explicit provider model IDs continue to work where the upstream API accepts them. Ships as part of the v3.0.0 release (task-014 carries the `Release-As: 3.0.0` footer; this task's commit is a plain `feat:`).

This task targets the **post-task-014 architecture**: a single `chat` tool with `chat`/`consensus`/`roundtable` modes, no `temperature`/`verbosity`/`use_websearch`/`enable_cross_feedback`/`cross_feedback_prompt`/`turn_prompt`/singular-`model` params, web search **capability-gated always-on** where `modelConfig.supportsWebSearch === true` (no tool arg), no `supportsTemperature` flags, and routing consolidated in `src/utils/modelRouting.js` with an exported `PROVIDER_PRIORITY`. Do NOT re-introduce any removed param or flag.

Model identifiers below were verified on 2026-07-11 (five research reports) — xAI, Mistral, DeepSeek, and OpenRouter IDs against live provider APIs; **Copilot IDs are documentation/changelog-corroborated, not live-verified** (`gpt-5.6-*` partly via secondary sources, `claude-sonnet-5` inferred from Copilot's mirror-Anthropic-ID pattern — the `listModels` RPC 403'd on the research account), so Copilot exact-ID confirmation is a manual release gate (see Notes / V2). Where a research finding conflicts with the original design doc's assumptions, the research finding wins.

### Shared model routing (Foundation)

One shared routing source (`src/utils/modelRouting.js` + a new OpenRouter discovery adapter module) owns provider defaults, curated friendly-alias→provider/model resolution, namespace rules, and OpenRouter metadata discovery. `chat` (all three modes) consumes it via the task-014 consolidation; no tool keeps a private routing table. Resolution order (from the design):

1. Honor an explicit provider namespace prefix (`copilot:`, `claude:`, `gemini:`, `openrouter:`).
2. Resolve a curated friendly alias to its canonical model ID + provider.
3. Treat a full OpenRouter `provider/model` slug, or an `openrouter:`-prefixed slug, as OpenRouter **without** requiring `OPENROUTER_DYNAMIC_MODELS=true`.
4. Preserve DeepSeek bare aliases for the native DeepSeek provider; OpenRouter DeepSeek models use their full slug/namespace.
5. Send unknown explicit provider model IDs to the selected provider unchanged — never silently substitute a default after explicit resolution.
6. Use the provider's curated default only when no model was supplied or a generic alias (`auto`) was selected.

Rolling aliases (`~author/model-latest`) remain explicit opt-in pass-through values, never promoted to friendly aliases.

### Capability updates

- **xAI**: map Converse `reasoning_effort` to Grok 4.5's `low`/`medium`/`high` (clamp unsupported levels; grok-4.5 cannot disable reasoning). Retain 500k context metadata, image support.
- **Mistral**: forward `reasoning_effort` (only `high`/`none` documented; `mistral-large-2512` does NOT accept the param); normalize `ThinkChunk`/`TextChunk`/`ReferenceChunk` in streaming (3 delta shapes) and non-streaming.
- **DeepSeek**: map reasoning via `thinking:{type}` + `reasoning_effort:{high|max}`; recognize `reasoning_content` (sibling of `content`) without dropping final answer text or throwing on valid empty-content turns.
- **OpenRouter**: standardized `reasoning`/`reasoning_details`; explicit opt-in web search (real per-request cost); `annotations[].url_citation` citations; `usage.cost` + `cost_details`; actual upstream `provider`; in-band SSE errors; optional referer; dynamic metadata discovery with a bounded cache.
- **Web-search reconciliation (design vs post-014):** post-014 attaches web-search tooling whenever `supportsWebSearch === true`. OpenRouter web search adds real cost, so **all OpenRouter curated models keep `supportsWebSearch: false`**; OpenRouter search engages ONLY via explicit opt-in in the model string (`:online` suffix on the slug), never silently. xAI grok-4.5's web-search decision is tied to the transport decision (see Design → xAI transport).

### Acceptance criteria

1. Each provider's `getSupportedModels()` returns **exactly** its curated catalog above (catalog test asserts the exact key set — for Copilot the exact set is the base `copilot` key PLUS the 8 curated model IDs; for OpenRouter it is exactly the 8 static slugs even after a discovery call has run, i.e. dynamic metadata is never merged into `getSupportedModels()`); `getDefaultModelForProvider(name)` in `modelRouting.js` returns the curated default (`xai→grok-4.5`, `mistral→mistral-medium-3-5`, `deepseek→deepseek-v4-pro`, `openrouter→z-ai/glm-5.2`; `openai→gpt-5.6`, `copilot→copilot` unchanged).
2. Every curated friendly alias and namespace prefix resolves to the intended provider + canonical ID from the `chat` tool entry (routing-parity test), in all three modes.
3. An unknown explicit provider ID passes through to its provider unchanged (no fallback substitution); an OpenRouter slug absent from a **fresh successful** bulk-catalog fetch fails before inference with `MODEL_NOT_FOUND` (a local classification, since the bulk `/api/v1/models` endpoint yields a whole-catalog list, not a per-slug HTTP 404); rolling aliases (`~author/model-latest`) and recognized decorations (`:online`, `:free`) are not treated as missing.
4. Grok, Mistral, DeepSeek, and OpenRouter reasoning options map to supported request values for every Converse `reasoning_effort` level (`none`/`minimal`/`low`/`medium`/`high`/`max`), with deterministic reduction where the provider exposes fewer levels; no invalid value is ever forwarded (Mistral `mistral-large-2512` and OpenRouter `kimi-k2.7-code`/`qwen3.7-*` special cases covered). **Reasoning request fields are capability-gated**: they are attached only when the resolved `modelConfig` indicates reasoning support, so an unknown/retired pass-through ID (e.g. an old Grok ID that would HTTP-400 on Grok 4.5 reasoning params) receives NO reasoning fields.
5. Mistral `ThinkChunk`/`TextChunk` (non-streaming array + all 3 streaming delta shapes), `ReferenceChunk` (ignored as metadata, not errored), DeepSeek `reasoning_content` (non-streaming sibling + streaming `delta.reasoning_content`), and OpenRouter `reasoning_details` (non-streaming + concatenated streaming) all normalize into the reasoning representation, keeping reasoning separate from answer text. Reasoning must **survive `providerStreamNormalizer`** (which today has no `thinking` branch and drops it) — proven by a normalizer/async test, not only a provider-unit test.
6. A DeepSeek (or any reasoning) turn with empty `content` but present `reasoning_content`, `reasoning_details`, or non-empty `tool_calls` does not throw `NO_RESPONSE_CONTENT` (an empty array does not count as present; nullable content normalizes to `''`).
7. OpenRouter: `:online` opt-in attaches web search and surfaces `annotations[].url_citation` citations; `usage.cost`/`cost_details.upstream_inference_cost` and top-level `provider` are captured in metadata; an in-band SSE `error` chunk (top-level `error` OR `finish_reason:"error"`, each detected independently) terminates the stream as **failed** while preserving already-received partial text (proven through the async/normalizer path). Mechanically verifiable opt-in: an ordinary (non-`:online`) request's outgoing payload contains no `:online` suffix, no `plugins`, and no web-search option.
8. OpenRouter discovery adapter distinguishes auth(401) / rate-limit(429) / timeout / malformed-response / catalog-miss; caches successes (bounded) and only **authoritative catalog-misses** negatively (short TTL) — transient failures (timeout, 429, malformed, abort) are NEVER negatively cached; concurrent lookups for the same slug are coalesced (single in-flight fetch); never caches/logs credentials or response bodies; an explicit slug proceeds to inference with conservative capabilities when discovery is unavailable but fails before inference on an authoritative catalog-miss; static curated models never trigger or depend on a discovery request.
9. `OPENROUTER_DYNAMIC_MODELS` is accepted as a deprecated no-op (explicit slugs work without it); `OPENROUTER_REFERER` is optional (omission is valid). When a referer/title is configured, the request sends `HTTP-Referer` plus a single canonical `X-OpenRouter-Title` header (NOT both `X-Title` and `X-OpenRouter-Title`), while still accepting the legacy `openrouterreferer`/`openroutertitle` config-key spellings as input.
10. Retired/legacy models are removed from catalogs, defaults, and help/doc text but still pass through as explicit IDs while their upstream accepts them; docs never present a retired model as a recommendation.
11. `pnpm run typecheck`, `pnpm run lint`, `pnpm run test:unit`, and the targeted per-provider test files all pass; catalog tests use mocked upstreams (no real API calls, no keys). `rg -w 'supportsTemperature|use_websearch|temperature|verbosity' src/providers/{xai,mistral,deepseek,copilot,openrouter,openai-compatible}.js` returns zero functional references (must not regress task-014's removals).
12. Docs (`docs/PROVIDERS.md`, `docs/API.md`, `docs/EXAMPLES.md`, `docs/ALTERNATIVE_PROVIDERS.md`, `README.md`, `CLAUDE.md`, `.env.example`) describe ONLY the current state — curated tables/defaults, OpenRouter full-slug + `openrouter:` examples, optional referer + removed dynamic-model gate, explicit opt-in web search + cost note, per-provider reasoning support/limits. Zero "changed/previously/no longer/v2" phrasing.
13. Commit is a single plain conventional `feat:` (no `Release-As:` footer — v3.0.0 comes from task-014). Never touch `package.json` version, `CHANGELOG.md`, or `.release-please-manifest.json`. Unrelated dirty/untracked worktree files stay untouched; staging is path-scoped to modernization files.

### Out of scope

- Migrating OpenRouter **inference** to `@openrouter/sdk` (discovery-only use, or plain fetch, is allowed).
- Adding new providers, changing credential/env-var names, or redesigning the public Converse response contract.
- Automatically following rolling OpenRouter aliases.
- Provider-aware final-message packing / tool-calling / citations wiring beyond what normalization requires (Mistral `ReferenceChunk` and DeepSeek tool-call reasoning-replay are recognized/flagged, not fully wired — see Notes).

## Design
<!-- DESIGN:BEGIN -->
### Split-friendly phase structure (required)

Implementation is done by **separate agents**, one phase at a time. Ownership is strict so per-provider phases never touch shared files:

- **Foundation** owns ALL shared-file edits: `src/utils/modelRouting.js`, the new OpenRouter discovery adapter module, and the shared `src/providers/openai-compatible.js` reasoning/normalization changes (DeepSeek and OpenRouter both extend this base).
- **Per-provider phases** (`xai`, `mistral`, `deepseek`, `copilot`, `openrouter`) each edit ONLY their own `src/providers/<name>.js` + their own `tests/unit/providers/<name>.test.js` (+ catalog fixtures). They consume Foundation's shared pieces via existing hooks; they do not edit `modelRouting.js` or `openai-compatible.js`.
- **Docs** owns the shared documentation sweep.

Each phase is independently executable after Foundation lands. The per-provider phases have no ordering dependency on each other (separate file ownership); all depend on Foundation.

### xAI transport decision (primary scope decision — flagged for codex review)

**Decision: migrate `src/providers/xai.js` from the deprecated Chat Completions endpoint to the xAI Responses API (`POST /v1/responses`).**

Rationale (per research-xai.md, verified 2026-07-11):
- xAI officially labels Chat Completions **"(Deprecated)"**; it returns **no reasoning content** and only "function calling" for tools.
- grok-4.5's headline capabilities that a v3.0.0 flagship should advertise — reasoning content and native web/X search (Agent Tools, `tools:[{type:"web_search"}]`) — are available **only** via the Responses API.
- The legacy `search_parameters` field on Chat Completions is deprecated (the separate Live Search API already returns HTTP 410 Gone); its future reliability is uncertain. Post-014, web search is always-on where `supportsWebSearch === true`, so keeping Chat Completions would send a deprecated/possibly-410 search field on **every** grok-4.5 request.
- The design's conservatism about NOT migrating OpenRouter transport does not apply here: OpenRouter's chat path works fine and is not deprecated; xAI's is officially deprecated and its advertised model's features require the new surface. "Effort is not a criterion" per the task brief — correctness wins.

Migration scope (confined to `xai.js` + its tests): messages→`input`, parse Responses output items (text + reasoning items), map reasoning to the reasoning event/metadata, attach `tools:[{type:"web_search"}]` when `supportsWebSearch` (post-014 gate), keep emitting the same unified event shapes (`start`/`delta`/`thinking`/`usage`/`end`/`error`). `supportsWebSearch: true`, `supportsImages: true`, `supportsReasoning: true` on `grok-4.5`. **Risk is materially lowered by an existing in-repo pattern:** `src/providers/openai.js` already drives the Responses API through the `openai` SDK (`responses.create`, image-part conversion, output-text / reasoning-summary / completion streaming events) — the xAI phase mirrors that shape. (For `thinking` events to survive downstream, the Foundation normalizer change F7 is required — see below.)

**Contingency (release-blocking, NOT an automatic runtime fallback):** a single failed smoke call does not prove transport incompatibility — a credential, entitlement, staged-rollout, or EU-region failure is not the same as an SDK/endpoint mismatch. Before concluding Responses is unworkable, try BOTH a minimal `openai`-SDK `responses.create` AND an equivalent raw HTTP `POST /v1/responses`. Never wire an automatic Chat-Completions fallback at runtime (it risks duplicate requests and masks auth/payload bugs). If Responses genuinely cannot ship, that is release-blocking: a reduced Chat-Completions release (which cannot satisfy the reasoning-content, Agent-Tools search, citation, or streaming-reasoning acceptance criteria) requires explicit plan re-approval, not a silent downgrade. Record the shipped path and the evidence in Notes.

**xAI deviation to document:** retired grok IDs (`grok-4-0709`, `grok-4-fast-*`, `grok-code-fast-1`) are **silently server-remapped** to `grok-4.3`/`grok-build-0.1` with HTTP 200 — there is NO retirement error for xAI, contradicting the design's general "surface a clear retirement error" assumption. Note this in code + docs.

### OpenRouter discovery adapter (Foundation)

New module (suggested `src/providers/openrouter-discovery.js`) using the **bulk public** `GET https://openrouter.ai/api/v1/models` endpoint (no auth, ~346 models, one un-paginated ~520KB payload) — chosen over the existing per-model `openrouter-endpoints-client.js` because the bulk response carries the structured top-level `reasoning` object (`{mandatory, default_enabled, supported_efforts, default_effort}`), a far better capability source than inferring from the flat `supported_parameters` list.

**Transport choice: plain `fetch`, not `@openrouter/sdk`.** Justification: the endpoint is public/unauthenticated and un-paginated, so the SDK's typing/pagination adds nothing material (the design gates SDK use on "materially improves typing or pagination"); the SDK is pre-1.0 with daily churn (`0.13.41`, published 2026-07-10). Avoiding it removes a version-churn risk with zero capability loss.

Adapter responsibilities: bounded success cache + short negative cache (reuse the TTL pattern in `openrouter-endpoints-client.js`); error taxonomy distinguishing auth(401) / rate-limit(429) / timeout / malformed / catalog-miss; short request timeout with timer cleanup and abort propagation; **single-flight coalescing** so concurrent lookups for the same slug share one in-flight fetch; **only authoritative catalog-misses are negatively cached** — transient failures (timeout, 429, malformed, abort) are never negatively cached (and a long-lived stale bulk snapshot must not mask a short negative TTL); never cache or log credentials/response bodies; expose per-slug metadata (context, max output, modalities, structured `reasoning`) for explicit slugs not in the static catalog. Because the source is the whole-catalog bulk list (no per-slug HTTP 404), "not found" = "absent from a fresh successful bulk fetch", surfaced to the provider as a local `MODEL_NOT_FOUND`. Static curated entries stay authoritative and never trigger or depend on discovery.

**Shared resolver + suffix parsing (Foundation, in `modelRouting.js`).** Add a named `resolveModelSpec(model, providers)` returning `{provider, canonicalModel, options}` (the design's resolution order; `options` carries flags such as `web_search` derived from an OpenRouter `:online` decoration). Keep the existing `mapModelToProvider(model, providers)` string return additively/back-compatible so task-014's concurrent `chat.js` call-plan builder is not forced to change; the unified `chat` tool consumes `resolveModelSpec`, and any glue edit that would be needed in `chat.js` to consume it belongs to Foundation (shared), NOT a per-provider phase. Centralize the curated friendly-alias→{provider, canonicalModel} table here as the single source (makes AC2's "every curated friendly alias" enumerable/verifiable). OpenRouter decoration parsing lives in the resolver: strip the `openrouter:` namespace, then parse `:online` (and preserve other composable suffixes such as `:free`) BEFORE static lookup/discovery, returning the bare canonical slug plus the `web_search` flag — never look up the decorated `...:online` string as a canonical/discovery ID (else `z-ai/glm-5.2:online` misses the static catalog and wrongly fails as dynamically absent). The provider attaches the plugin from the flag exactly once (either keep `:online` on the slug OR send `plugins:[{id:'web'}]`, never both).

### openai-compatible.js reasoning + hook plumbing (Foundation)

`src/providers/openai-compatible.js` is the shared base for `deepseek.js` and `openrouter.js`. **Verified against current code (2026-07-11), the four contracts below are all NECESSARY — without them the DeepSeek and OpenRouter phases would be forced to edit this shared file, breaking the split:**

1. **`transformRequest` request-side contract (BLOCKER — today it can't see the effort).** `invoke` destructures `reasoning_effort` out and marks it unused (`eslint-disable no-unused-vars`); `transformRequest(payload, {model, modelConfig})` never receives it or `signal`. So DeepSeek's `transformRequest` (D2) and OpenRouter's request mapping (O4) literally cannot read the requested effort. Foundation must widen the context to `transformRequest(payload, {model, modelConfig, reasoningEffort, signal})`, exposing ONLY sanitized provider-relevant options (do NOT reintroduce any removed task-014 arg).
2. **Async `resolveModelConfig` hook (BLOCKER for OpenRouter dynamic metadata + AC1).** The base closes over the static `supportedModels` map for image validation, timeout, output cap, reasoning gating, and the `transformRequest` context. OpenRouter's monkey-patched `getModelConfigAsync`/`dynamicModels` map (openrouter.js) does NOT influence the base, and it currently makes `getSupportedModels()` expand past the curated 8 after discovery (violating AC1). Foundation adds an optional async `resolveModelConfig(model, {config, signal})` hook the base calls to obtain a request-local model config; dynamic OpenRouter metadata rides through this (cached in the discovery adapter, request-local) and is NEVER merged into `getSupportedModels()`.
3. **Non-streaming reasoning + validity fix (DeepSeek + OpenRouter).** Read `choice.message.reasoning_content` into `result.metadata` alongside `content`. Replace the `if (!content) throw NO_RESPONSE_CONTENT` guard (which runs BEFORE `transformResponse`) with a generic validity check that accepts a turn carrying any of: non-empty `content`, non-empty `reasoning_content`, non-empty `reasoning_details`, or a non-empty `tool_calls` array (an empty array must NOT count merely for being truthy). Normalize nullable `content` to `''`. Missing reasoning stays valid.
4. **Streaming field fix + per-chunk hook with an EXPLICIT result contract.** Change `choice.delta?.reasoning` to `choice.delta?.reasoning_content` (gated by `modelConfig.supportsReasoning`, yields `type:'thinking'`). Add an optional per-chunk hook `transformStreamChunk(chunk, streamState)` returning `{ events: [], metadataPatch: {}, suppressDefault: false, terminalError: null }`:
   - `events` — extra normalized events to yield (e.g. `thinking`);
   - `metadataPatch` — merged into the final `end` metadata (carries `reasoning_details`, `annotations`, `usage.cost`/`cost_details`, top-level `provider`, request id — none of which the streaming path's synthetic `transformResponse` object currently exposes);
   - `suppressDefault` — skip the base's default delta handling for that chunk;
   - `terminalError` — emit exactly ONE failure event and return WITHOUT a later successful `end`, leaving already-emitted deltas intact (the base currently converts per-chunk exceptions into *recoverable* `CHUNK_PROCESSING_ERROR` events and keeps going — that is wrong for OpenRouter's fatal in-band errors).

**`providerStreamNormalizer` reasoning passthrough (BLOCKER — Foundation-owned, TODO F7).** `src/async/providerStreamNormalizer.js` per-provider branches (`normalizeXAIStream` etc.) handle `start`/`delta`/`usage`/`end`/`error` but have **no `thinking` branch**, so any `thinking` event is silently dropped before it reaches the async job / `check_status`. Foundation must add reasoning passthrough (a `thinking` branch, and reasoning-detail carry-through on `end` metadata) to the xai/mistral/deepseek/openrouter branches, with a normalizer test proving reasoning survives. This is why the claim "the normalizer is untouched" was wrong and is corrected here.

These shared edits (`openai-compatible.js` + `providerStreamNormalizer.js`) are the ONLY shared-provider/async-file edits; DeepSeek and OpenRouter phases then touch only their own files and rely on these contracts.

### Reasoning-level mapping (Converse `reasoning_effort` → provider request)

Converse levels: `none` / `minimal` / `low` / `medium` / `high` / `max` (default `medium`). **All mappings are capability-gated**: reasoning fields are attached ONLY when the resolved `modelConfig` indicates reasoning support, so unknown/retired pass-through IDs get no reasoning fields (see AC4). Per provider:

- **xAI grok-4.5** (Responses API; values `low`/`medium`/`high`, default `high`, cannot disable): `none`→`low`, `minimal`→`low`, `low`→`low`, `medium`→`medium`, `high`→`high`, `max`→`high`. (No "none"/off exists — must clamp, else HTTP 400.)
- **Mistral** (values `high`/`none` only; `mistral-medium-3-5`/`mistral-small-2603` support it, `mistral-large-2512` does NOT): `none`→`"none"`; every other level (`minimal`/`low`/`medium`/`high`/`max`)→`"high"`. For `mistral-large-2512`, never send `reasoning_effort`. **This is "preserve enabled-reasoning intent," NOT nearest-level reduction:** Converse's default `medium` maps to `"high"` (thinking on) rather than to `"none"`, matching the DeepSeek pattern where only `none` disables. (research-mistral.md §4 floats the alternative "anything below high → none"; rejected here so the reasoning-capable default doesn't silently run thinking-off. Codex-flagged wording — documented, not a bug.)
- **DeepSeek** (`thinking:{type}` + `reasoning_effort:"high"|"max"`): `none`→`{thinking:{type:"disabled"}}` (omit `reasoning_effort`); `minimal`/`low`/`medium`/`high`→`{thinking:{type:"enabled"}, reasoning_effort:"high"}`; `max`→`{thinking:{type:"enabled"}, reasoning_effort:"max"}`.
- **OpenRouter** (`reasoning:{effort|enabled|exclude}`) — **metadata-driven from each model's structured `reasoning` object** (from the discovery adapter / static override), NOT hard-coded per slug: (1) `reasoning.mandatory:true` (`moonshotai/kimi-k2.7-code`) → always `{enabled:true}`, ignore any `none`/exclude; (2) non-empty `supported_efforts` (`z-ai/glm-5.2`, `deepseek/deepseek-v4-*` → `[xhigh,high]`) → clamp into that set: `max`→`xhigh`, `high`/`medium`/`low`/`minimal`→`high`, `none`→`{enabled:false}`; (3) optional with no effort list (`qwen/qwen3.7-max`, `qwen/qwen3.7-plus`, `moonshotai/kimi-k2.6`) → binary `none`→`{enabled:false}`, else `{enabled:true}`; (4) `openrouter/auto` → pass the request through (router selects the effort), don't fabricate an effort; (5) unavailable/unknown metadata → omit reasoning controls conservatively. Note `exclude:true` ≠ disabled (the model still reasons, just hidden) — Converse `none` uses `{enabled:false}` where supported, never `exclude`.

### Context Manifest

**Provider architecture.** Every provider exports an object implementing `async invoke(messages, options) => {content, stop_reason, rawResponse, metadata}` (or an async generator of `start`/`delta`/`thinking`/`usage`/`end`/`error` events when `options.stream`), plus `validateConfig`, `isAvailable`, `getSupportedModels`, `getModelConfig(name)`. Each provider holds a `SUPPORTED_MODELS` map keyed by canonical ID; each entry carries capability flags (`contextWindow`, `maxOutputTokens`, `supportsStreaming`, `supportsImages`, `supportsWebSearch`, `supportsReasoning`, `timeout`, `description`, `aliases[]`). `resolveModelName(name)` in each provider matches exact IDs, then aliases, then returns the input unchanged (passthrough for unknown IDs — this is what keeps explicit retired IDs working).

- `xai.js` and `mistral.js` are **direct-SDK** providers (xai uses the `openai` npm SDK against `baseURL: https://api.x.ai/v1`; mistral lazy-loads `@mistralai/mistralai`). They implement their own `invoke` + `_createStreamingGenerator`.
- `deepseek.js` and `openrouter.js` are thin wrappers over `createOpenAICompatibleProvider({baseURL, supportedModels, validateApiKey, transformRequest, transformResponse, defaultParams, ...})` in `openai-compatible.js`, which owns the shared OpenAI-SDK request/stream logic. `openrouter.js` additionally monkey-patches `getModelConfig`/`getModelConfigAsync`/`invoke` for dynamic models and header injection.
- `copilot.js` wraps `@github/copilot-sdk` (spawns the `copilot` CLI over JSON-RPC); model IDs are lowercase dot-versioned (e.g. `claude-opus-4.8`, `gemini-3.1-pro-preview`) and pass through to the backend unvalidated (`createSession({model})`).

**modelRouting.js (shared).** `getDefaultModelForProvider(name)` holds a per-provider default map with **stale** entries today (`xai:'grok-4-0709'`, `mistral:'magistral-medium-2506'`, `deepseek:'deepseek-reasoner'`, `openrouter:'qwen/qwen3-coder'`) — Foundation updates these to the curated defaults. `mapModelToProvider(model, providers)` does namespace-prefix checks (`copilot:`/`claude:`/`gemini:`), exact-keyword routing (`includes('grok')→xai`, `includes('mistral')→mistral`, `includes('deepseek')→deepseek`, `includes('qwen')/'kimi'/'moonshot'→openrouter`), and slash-format handling (checks each native provider's `getModelConfig`, else routes to openrouter). Task-014 adds an exported `PROVIDER_PRIORITY` constant here and repoints the tools to import from this module — Foundation builds on that, not on the pre-014 inline copies.

**openai-compatible.js reasoning bugs (to fix in Foundation).** Non-streaming (~`choice.message?.content` read, then `if (!content) throw NO_RESPONSE_CONTENT`) never reads `reasoning_content` and throws on any falsy content — breaks DeepSeek thinking-mode turns. Streaming checks `choice.delta?.reasoning` (wrong field; DeepSeek/OpenRouter use `reasoning_content` / `reasoning_details`) gated behind `modelConfig.supportsReasoning`, so streamed reasoning is never emitted.

**openrouter.js existing issues (to fix in the openrouter phase).** `transformResponse` reads `usage.prompt_cost`/`completion_cost`/`total_cost` — these fields do not exist; the real field is `usage.cost` (+ `usage.cost_details.upstream_inference_cost`). `invoke` throws `OpenRouterProviderError` when no referer is configured (must become optional). The `OPENROUTER_DYNAMIC_MODELS` gate rejects slash-format models unless set (must become a deprecated no-op). Headers use `X-Title` (legacy; canonical is `X-OpenRouter-Title`, still accept the `openroutertitle` config key). Static `SUPPORTED_MODELS` today lists retired generations (`qwen/qwen3-235b-a22b-thinking-2507`, `qwen/qwen3-coder`, `moonshotai/kimi-k2`, `z-ai/glm-4.6`, `openrouter/auto`) — replaced by the 8 curated slugs.

**Provider stream normalizer.** `src/async/providerStreamNormalizer.js` consumes the unified event shapes providers yield, but its per-provider branches (`normalizeXAIStream` etc.) currently handle only `start`/`delta`/`usage`/`end`/`error` — there is **no `thinking` branch**, so reasoning events are silently dropped before reaching async jobs / `check_status`. Foundation must add reasoning passthrough here (TODO F7); the rest of the async job plumbing is untouched.
